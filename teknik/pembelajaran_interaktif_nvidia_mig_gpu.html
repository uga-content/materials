Apa itu Multi-Instance GPU (MIG)?

**Multi-Instance GPU (MIG)** adalah fitur arsitektur hardware (diperkenalkan sejak arsitektur NVIDIA Ampere A100 & Hopper H100) yang memungkinkan 1 fisik GPU raksasa diisolasi secara hardware menjadi hingga **7 Instance GPU terpisah yang mandiri**.

Setiap *instance* memiliki **sumber daya perangkat keras yang terjamin** (Streaming Multiprocessor/SM, L2 Cache, Memory Controller, dan VRAM khusus). Tidak ada saling perebutan daya komputasi (*Noisy Neighbor*) antar tenant.

1. Hardware Level Isolation

Partisi terjadi di tingkat silikon fisik, bukan sekadar software driver. Memori L2 Cache dan Crossbar Bus dipisah secara tegas.

2. Guaranteed Quality of Service (QoS)

Performa dan latensi setiap *instance* 100% konsisten dan terprediksi, sangat ideal untuk inferensi AI berlatensi rendah.

3. Fault & Error Isolation

Jika aplikasi pada Instance 1 mengalami *Out-Of-Memory (OOM)* atau *kernel crash*, 6 instance lainnya TETAP BERJALAN tanpa terganggu.

Perbandingan: Time-Slicing vs MIG Hardware Partitioning

Pahami perbedaan mendasar antara membagi GPU secara software (Time-Slicing) vs membagi GPU secara hardware (MIG).

Shared GPU (Time-Slicing / Software) Unpredictable

Semua proses aplikasi mengantre waktu giliran (*time slices*) untuk mengakses CUDA Cores & VRAM yang sama.

Noisy Neighbor: Jika Process A melakukan perkalian matriks LLM berat, Process B akan mengalami *lag spike*.
Shared Memory Failure: Jika Process A kehabisan VRAM (OOM), seluruh GPU bisa mengalami *Reset Kernel*!
NVIDIA MIG (Hardware Partitioning) Deterministic

GPU dipisah secara silikon fisik. Setiap instance memiliki memory pipeline, L2 cache, dan SM controller terisolasi.

Zero Latency Cross-talk: Beban kerja pada Instance 1 sama sekali tidak memengaruhi latensi Instance 2.
Fault Isolation: Jika Process A mengalami OOM, Instance 2 TETAP BERJALAN 100% normal.
