Prinsip Lokalitas: Ruang Kerja Sofia

Mengapa sistem hirarki memori bisa bekerja sangat cepat? Karena program memiliki sifat Temporal dan Spatial Locality.

📖 Meja Kerja (L1/L2 Cache) 1–10 ns

Kapasitas kecil. Sofia menaruh buku yang sedang dibaca berulang-ulang di sini (Temporal Locality).

📚 Rak Buku (Main Memory / DRAM) 30–90 ns

Saat mengambil 1 buku topik COA, Sofia sekalian membawa 1 set buku COA berdekatan ke meja (Spatial Locality / Cache Block).

🗄️ Lemari Arsip (Hard Disk / SSD) 5–20 ms

Kapasitas sangat besar, menyimpan arsip jarang dipakai, tetapi butuh waktu lama untuk mengambilnya.

💡 Poin Kunci untuk Mahasiswa: CPU tidak mengakses 1 byte dari RAM ke Cache, melainkan 1 Cache Line / Block (32–128 byte) sekaligus untuk memanfaatkan Spatial Locality.

Analisis Ukuran Page Table

Mengapa Sistem 64-bit Wajib Menggunakan Multi-Level Page Table?

Perbandingan ukuran memori yang habis hanya untuk menyimpan Single-Level Page Table (asumsi Page Size = 4 KB / 12-bit offset, PTE = 4 byte).

Arsitektur 32-Bit (Single Level)
4 MB / proses

VPN = 32 - 12 = 20 bit.
Jumlah entri = 220 = 1.048.576 page.
Ukuran = 1.048.576 × 4 byte = 4 MB.
Jika ada 200 proses = 800 MB RAM terbuang!

Arsitektur 64-Bit (Single Level)
16 Exabyte / proses

VPN = 64 - 12 = 52 bit.
Jumlah entri = 252 (4 Kuadriliun page).
Ukuran = 252 × 4 byte = 16 Exabyte.
TIDAK MASUK AKAL! Tidak ada RAM sebesar ini.

Solusi: x86-64 4-Level Page Table
Puluhan KB / proses

Alamat 48-bit dibagi: PML4 (9b) → PDP (9b) → PD (9b) → PT (9b) → Offset (12b).
Hanya tabel yang benar-benar dipakai yang dialokasikan (Sparse Address Space).
